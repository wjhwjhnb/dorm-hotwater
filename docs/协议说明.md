# 协议说明

> 本文是逆向乐校通小程序后整理出的通信协议。用于理解本项目在做什么，不要用于攻击任何系统。

---

## 一、蓝牙帧格式（水控器 ↔ 手机）

### 发送帧（手机 → 水控器）

```
A5  <len>  <d>  <g>  <c1>  <c2>  <c3>  <data...>  <sum>

d, g   各 1 字节随机数
c1 = u(rns1, g, d)
c2 = u(rns0, g, d)
c3 = u(cmd,  g, d)
len    = 5 + len(data)            ← 即 <len> + 3 == 帧总字节数
sum    = (d + g + c1 + c2 + c3 + data 逐字节累加) & 0xFF

其中   u(x, t, r) = (0xAA + (x ^ t ^ r)) & 0xFF

最后整体转义： A5 → 1BE7， 1BE7 → 1B00E7
（因为 A5 是帧头，载荷里出现 A5 会造成歧义）
```

### 接收帧（水控器 → 手机）

```
A5  <len>  <rns3> <rns2> <rns1> <rns0> <cmd> <type> <ver> <way> <status> <data...> <sum>
            └明文┘  └────────── 这 7 个字节用下式解码 ──────────┘

i(x, t, r) = ((x - 0xAA) & 0xFF) ^ t ^ r
其中解码时 t = rns2，r = rns3
```

### 帧长规则

`<len>` 字段 + 3 = 帧的总字节数。

**这条规则很关键**：调试时如果收到的数据长度对不上，说明帧被截断了
（BLE 的 ATT 通知可能分包，必须把多包拼起来再判断）。

## 二、命令表

| cmd | 作用 | data 内容 |
|---|---|---|
| `F0` | 取设备信息 | 空。回复 data = SN(8B) + MAC(6B) + IMEI(8B) + … |
| `08` | 取随机数 | 空 |
| `02` | 授权 | `type(1B) + ID(8B)`，type 用 `01` |
| `32` | 授权（部分机型） | 同上 |
| `06` | **开阀** | `type(1B) + systemData(16B) + systemTime(6B)`，type 用 `01` |
| `46` | 开阀（机型 01/93 专用） | 同上 |
| `14` | **关阀** | `"00" + ID(8B)` |
| `01` | appKey 授权 | — |
| `07` | 更新 | — |

### 返回码（回复 data 的头 2 个字符）

| 命令 | 值 | 含义 |
|---|---|---|
| 02 | `00` / `01` | 正常 |
| 02 | `03` | 设备正忙 |
| 02 | `06` | 该账户正在使用中 |
| 06 | `00` / `AA` | 成功 |
| 06 | `01` | **授权失败**（令牌被拒） |
| 06 | `03` | 设备正忙 |
| 14 | `00` | 关阀成功 |
| 14 | `01` | 设备本来就是关闭的 |
| 14 | 其他 | 设备正忙 |

## 三、开阀完整链路

**设备只认服务器签发的令牌**，所以必须「蓝牙 + 服务器」配合：

```
┌ BLE ────────────────────────────────────────────────┐
│ ① cmd F0   取设备信息 → SN / MAC                     │
│ ② cmd 08   取随机数                                  │
│ ③ cmd 02   授权(type=01) → 设备给出"挑战"             │
│      machinedata   = 回复 data[10:18]                │
│      possystemtime = 回复 data[18:24]                │
│      openClientType= 回复 data[1]                    │
└──────────────────────────────────────────────────────┘
┌ HTTP ───────────────────────────────────────────────┐
│ ④ GET  mgapp/machine/getMachineByMac                 │
│         ?mac=AA:BB:..&typeId=1                       │
│    → deviceVer（如 "01,07"）、roominfo、machineName   │
│ ⑤ POST bath/handleData                               │
│    { typeId, channelWay:1, machineId:SN,             │
│      deviceVer, openClientType, machineInfoJson:{    │
│        machineData, machineRandom, posSystemTime,     │
│        temperature }, machineDataFull, randomKey }    │
│    → 服务器签发 systemData(16B) + systemTime(6B)      │
└──────────────────────────────────────────────────────┘
┌ BLE ────────────────────────────────────────────────┐
│ ⑥ cmd 06   data = type(01) + systemData + systemTime  │
│    → 回复 data 以 "00"/"AA" 开头 = 开阀成功            │
└──────────────────────────────────────────────────────┘

关阀不需要服务器：cmd 14, data = "00" + ID(8B)
```

## 四、服务器接口

### 域名

| 域名 | 用途 |
|---|---|
| `topservice.lxt6.cn` | 配置下发、登录、验证码 |
| `v3-app.lxt6.cn` | 用户信息等 |
| `v3-prod-beta-app.lxt6.cn` | 设备/开阀令牌/广告 |
| `op-dau.lxt6.cn` | 活跃上报 |
| `sos-api.lxt6.cn` | 白名单状态 |

### 请求头

```
content-type : application/json
X-Sid        : 2021011300001
X-Sign       : md5("1FF75E512" + F)
X-B3-TraceId : 16 位随机小写十六进制
X-B3-SpanId  : 同上
X-Product-Ver: <客户端版本>#?<小程序版本>
X-Mobile-Info: <平台>#?<机型>#?<系统>
X-clientType : 4
X-Ghost      : ★ 见下
x-token      : 登录票据（未登录时不带）
Cookie       : 同上
```

### 签名 F 的取法

| 方法 | F |
|---|---|
| POST | 请求体的**原始字符串**（就是实际发出去的那串） |
| GET | 查询串的**原始形式**，如 `account=1476...&topservice=true`（无参数时为空串） |

### ★ X-Ghost —— 设备时间指纹（最容易踩的坑）

它**不是随机数**，而是把当前时间编码进去：

```
X-Ghost = 累加校验(2 位) + 毫秒时间戳HEX(12 位) + 异或校验(2 位)

时间戳   = Date.now().toString(16)，补零到 12 位，转大写
累加校验 = (时间戳每个字节相加) % 256 → 2 位十六进制
异或校验 = (时间戳每个字节异或)      → 2 位十六进制

例：8701A12EC445AEA1
    时间戳 01A12EC445AE = 1791785977262 ms
    累加 (01+A1+2E+C4+45+AE)%256 = 135 = 0x87  ✓
    异或 01^A1^2E^C4^45^AE      = 0xA1          ✓
```

**填错这个值，服务器会返回 `-45 请求已过期,请核对设备时间!`** ——
错误信息其实已经提示了是"时间"的问题。

### 登录相关

```
① GET  user/authentication/getCode?account=<手机号>&topservice=true
       → Data = base64 的 PNG 验证码（130×48，5 位数字）

② GET  user/authentication/moblieMessageV2
       ?studentMobile=<手机号>&funFlag=1&platform=1
       &verificationCode=<图片验证码>&topservice=true
       → 短信发到手机
       ⚠ 必须和第①步在【同一会话】里（验证码绑定 __jsluid_s cookie），
         且验证码有效期很短（约 1 分钟），两步要在同一进程内尽快完成
       ⚠ platform 的值是字符串 "1"，不是 "windows"

③ POST user/login/userLoginV2WithEncrypt
       body = {"data": base64( JSON.stringify({
                  studentMobile, loginPassword, code, topservice:true
              }) )}
       内层 JSON 的键顺序必须是 studentMobile → loginPassword → code → topservice
       → 响应头 Set-Cookie: tokenInfo=<学号>#?<会话哈希>
```

> 关于 `WithEncrypt`：源码里对 `userLoginV2` 等 4 个接口会
> `e += "WithEncrypt"; S = JSON.stringify({data: jsBase64.encode(S)})`。
> **名字叫 Encrypt，实际只是 base64**，没有加密。

### 常见错误码

| Code | 含义 |
|---|---|
| `-44` | 用户身份失效，需重新登录 |
| `-45` | 请求已过期（X-Ghost 算错）／验证码错误或过期／功能版本非法 |
| `-302` | platform 值错误 |
| `0` | 成功 |

## 五、调试建议

1. **先看帧长**：`<len> + 3` 对不对？对不上就是被截断了。
2. **先发 F0**：能拿到 SN/MAC 说明 BLE 链路和帧格式都没问题。
3. **`-45` 优先怀疑 X-Ghost**，不是先怀疑票据。
4. **设备被占用**时 cmd 02 会回一个很短的状态码（`03` 或 `06`），
   而不是完整的 26 字节挑战数据 —— 别把它当成"帧格式错了"。
