# 常见问题

## 安装与配置

**Q：双击「一键配置」一闪就没了 / 提示找不到 Python**

正常情况下它会**自动帮你装 Python**（下载官方安装包，静默安装，只需当前用户权限，
不会弹管理员授权）。装完继续跑配置向导。

如果它说装不上，手动装一个 [Python 3.9+](https://www.python.org/downloads/)，
安装时**务必勾选 "Add python.exe to PATH"**。

⚠️ **不要用微软商店版的 Python** —— 那个 `python` 是个假壳子，装不了依赖。
所有启动脚本都会自动跳过它。

**Q：装依赖很慢 / 卡住**

`ppllocr` 依赖 `onnxruntime`，第一次要下几百 MB。耐心等，或者手动换镜像：

```
python -m pip install ppllocr requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**Q：没装 Python 也能用吗**

能。双击「开热水」时如果找不到 Python，它会**自动转去跑「一键配置」**，装完再回来。

## 登录

**Q：为什么要登录？不能直接用吗**

水控器只认**服务器签发的**凭证，而凭证要登录后才能拿到。这是设备侧的防绕过设计。

**Q：需要短信验证码吗**

**不需要。** 登录只要 **手机号 + 密码 + 图片验证码**，图片验证码由本地模型自动识别。

这一点很多人会搞错（我一开始也搞错了）：登录接口的参数名叫 `code`，
很容易以为是短信码，但**它其实是图片验证码**。

已实测验证：用**假密码 + 真图片码**请求，服务器回
`{"Code":-45,"Message":"登录账号或密码不正确!,还有2次机会!"}`
—— 说明验证码先被接受了。如果 `code` 是短信码，这里应该报"验证码错误"。

那 `moblieMessageV2` 是干什么的？它属于**忘记密码/重置密码**流程，跟登录无关。

**Q：⚠️ 我的密码安全吗**

- 密码**只用于登录**，之后用 Windows DPAPI 加密存在本机
  （`state/credentials.dat`）——**只有你这台电脑 + 这个 Windows 账户能解开**，
  文件拷到别的机器打不开
- 不写日志、不上传任何地方
- 源码是公开的，可以自己看 `src/credentials.py` 和 `src/lxt_login.py`
- 不想存：配置时选 `n`，或跑 `python src/credentials.py --clear` 删掉

**Q：提示「登录账号或密码不正确，还有N次机会」**

**密码错了，而且服务器在倒计时锁号 —— 立刻停手，别再试。**

确认密码（注意大小写）后重新跑。反复错可能锁号。

**Q：为什么密码不能自动重试**

因为重试会消耗尝试次数，错多了锁号。验证码识别错了会自动换一张重试（不消耗密码机会），
但**密码不会自动重试**，这是故意的。

**Q：图片验证码认错了怎么办**

不用管，代码会自动换一张重试（最多 8 轮）。实测 ppllocr 对这个 5 位数字验证码
识别率 5/5。

识别引擎都不可用时，会弹出图片让你手动输——永远有兜底。

**Q：登录成功但提示「没拿到 tokenInfo」**

服务端没按预期下发 cookie。请提 issue 附上**打码后的**响应头。

## 使用

**Q：提示「用户身份失效 (-44)」**

会话过期。程序会**自动重新登录**（验证码还是自动识别），你不会察觉。
如果自动重登也失败，跑一次「一键配置」。

实测会话能活 10 小时以上。

**Q：提示「请求已过期，请核对设备时间 (-45)」**

这个码有多义，要结合上下文看：

| 场景 | 真实含义 |
|---|---|
| 取验证码时 | 图片验证码过期（重新取一张即可） |
| 登录时 | 密码错误（看 Message 里的文字） |
| 开阀时 | 设备未授权 |

核心是看 `Message` 的文字，别只看码。

**Q：开阀成功了但水很小 / 没水**

那是水压或设备本身的问题，不是本工具的问题。工具只负责让水控器放行。

**Q：能关阀但开阀失败**

开阀要联网（服务器要签发指令）。检查网络。

**Q：关阀时提示「这次用了几分钟」是怎么算的**

本机记录的。如果你在**另一台电脑**或**手机上**开的阀，这台电脑就没有开阀记录，
时间会不准（但关阀本身照常工作）。

**Q：会多扣钱吗**

不会。正常用水计费，跟你用小程序开一样，走你自己的账户。

**Q：需要开蓝牙吗**

**不需要。** `deviceVer` 第二段是 `07` 的设备是 4G 机，开阀关阀都由服务器下发指令。

> 一开始的实现是蓝牙直连（扫设备 → 连接 → 走帧协议握手）。能用，但有两个问题：
> 一是**手机连着这台设备时电脑就连不上**（蓝牙设备一次只能被一个主机连接），
> 二是每次要扫描+握手，慢。后来发现根本不用蓝牙，就换掉了。
>
> 旧蓝牙代码还在 `src/` 里留着（`lxt_ble.py` / `lxt_nb.py` / `lxt_open.py`），
> 如果你的设备是蓝牙机可以参考。

## 兼容性

**Q：我们学校设备型号不一样，能用吗**

先跑「一键配置」看 `deviceVer`：

- 第二段是 **`07`** → 4G 机，走服务器下发，✅ 能用
- 其他 → 可能是蓝牙机，需要走 `src/lxt_ble.py` 那套（已实现并验证过）

欢迎提 issue 附上你的 `deviceVer` 和 `getMachineByMac` 的返回。

**Q：支持手机 / Mac 吗**

目前只做了 Windows（依赖 Windows DPAPI 存凭据、`.bat` 启动器、`cscript` 建快捷方式）。
核心协议代码是跨平台的，理论上改改就能在 Linux / macOS 上跑。

**Q：宿舍号输了没找到**

输完整一点，比如 `15栋402`。**房号会重名**——实测某校 1343 个房间里 `402` 有 4 个
（不同楼栋各一个），而且还有 `A402 / B402 / C402` 这种**真实存在**的房号。

所以配置时会把候选**全列出来**（精确匹配排前面，只是"含有"的排后面并标注），
**看清楚地址再选**。

## 安全边界

**Q：这个工具会不会被别人拿去控制我的设备**

不会。工具用的是**你自己的**登录凭证，只能操作你账号权限内的设备。
它不知道也无法获取别人的账号。

**Q：能帮别人开阀吗**

不能，也不应该。见 `LICENSE` 里的使用须知。

**Q：为什么不做"自动过短信验证码"**

**因为根本不需要短信。** 登录只要图片验证码，而图片验证码本地就能识别。

（如果哪天学校换成强制短信登录：短信是发到用户自己手机上的，程序拿不到；
想让程序拿到只能靠手机装转发 App 或接打码平台，两条路都不现实。到那时候的正确做法是
"登录一次 + 保活长期免登录"。）
